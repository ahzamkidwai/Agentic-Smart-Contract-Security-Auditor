audit-explainer

Turns raw static-analysis findings into plain-English, file-and-line-grounded audit reports — for a GitHub repo or a single pasted contract.

not checked

Pipeline & anti-hallucination guardrails

1. IngestGitHub URL is cloned, or pasted code is written to a scratch .sol file. Zip-slip and size-limit guarded.
2. Static analysisSlither runs in an isolated venv against the real compiler output — findings, not guesses.
3. LocateExact file + line numbers are read from Slither's own source_mapping, never from the LLM.
4. GroundDeterministic checks (return-value handling, compiler-bug applicability, CEI ordering) compute facts the LLM must defer to.
5. Explain (RAG)An SWC-Registry retriever + temperature-0 LLM writes the plain-English explanation, constrained to only the flagged lines.
6. Verify & renderFix snippets are syntax-validated (auto-repaired once) before being shipped; a PDF/JSON report is produced.

Why this shouldn't hallucinate

  • Grounded, not generated, locations. File name and line number shown on every finding come directly from Slither's source_mapping — the model never invents them.
  • Temperature = 0 for the explainer LLM, and the prompt forbids describing anything not visible in the flagged source lines.
  • Deterministic "ground truth facts" (e.g. "return value IS checked") are computed in Python and injected into the prompt — the model is instructed to defer to them rather than re-guess.
  • Detector-scoped prompting stops the model from borrowing risk language from an unrelated vulnerability class just because it "sounds related."
  • SWC references are whitelisted to IDs that actually appear in the retrieved registry context, not whatever the model recalls.
  • Fix snippets are statically validated (balanced delimiters, valid low-level-call syntax) with a single automatic repair attempt before falling back to "manual review required" rather than shipping broken code silently.

The repo is cloned into an isolated workspace, its Hardhat/Foundry contracts are located, dependencies installed, and every .sol file is run through the pipeline above — including files with zero findings.

The pasted code is written to a private temp file and run through the exact same Slither → grounding → RAG-explainer pipeline as the GitHub flow.
