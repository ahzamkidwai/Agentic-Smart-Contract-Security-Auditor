# SWC-105: Unprotected Ether Withdrawal

## Summary
A function that transfers ETH out of the contract is missing an access
control check, so any address - not just the intended owner or recipient -
can trigger it and drain the contract's balance.

## Why it matters
This is one of the most directly exploitable bug classes: an attacker
simply calls the function once and takes the funds. No complex setup is
required.

## Typical patterns Slither flags
- A `public`/`external` function containing `.transfer()`, `.send()`, or a
  low-level `.call{value: ...}` with no preceding `require(msg.sender ==
  owner)` (or equivalent modifier such as `onlyOwner`).

## Typical fix
- Add an explicit access-control check or modifier (`onlyOwner`,
  role-based access control) before any function that moves funds out of
  the contract.
- Follow the checks-effects-interactions pattern: verify permissions and
  update state before making the external transfer.
