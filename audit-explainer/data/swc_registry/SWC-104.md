# SWC-104: Unchecked Call Return Value

## Summary
Solidity's low-level calls (`call`, `delegatecall`, `send`) and some older
ERC-20 `transfer`/`transferFrom` implementations return a boolean indicating
success instead of reverting on failure. If the caller doesn't check that
boolean, a failed transfer or call is silently ignored.

## Why it matters
Code can proceed as if a payment or external call succeeded when it
actually failed - crediting a user for a transfer that never happened, or
letting accounting drift out of sync with actual token balances.

## Typical patterns Slither flags
- `address.call{value: x}("")` or `token.transfer(...)` whose return value
  is never assigned to a variable or checked.
- `.send()` used for ETH transfers without checking the returned bool.

## Typical fix
- Always capture and check the return value:
  `(bool ok, ) = to.call{value: amount}(""); require(ok, "transfer failed");`
- For ERC-20 interactions, prefer OpenZeppelin's `SafeERC20` wrapper, which
  reverts on failure and also handles non-standard tokens that don't return
  a bool at all.
