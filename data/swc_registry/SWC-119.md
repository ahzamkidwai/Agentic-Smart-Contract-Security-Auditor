# SWC-119: Shadowing State Variables

## Vulnerability Description
A contract declares a state variable (or local variable) with the same name as a variable inherited from a base contract. Instead of overriding the base contract's variable, Solidity creates a *second* variable in storage. The base contract's functions will operate on the base variable, while the derived contract's functions operate on the new shadowed variable. This leads to severe logic bugs, especially with critical variables like `owner`.

## Severity
High

## Detection Rules & Indicators
- A state variable in a derived contract has the exact same name as a state variable in a parent contract.
- A local variable in a function has the same name as a state variable.

## Vulnerable Example
```solidity
contract Base {
    address public owner;
    
    constructor() { owner = msg.sender; }
    
    modifier onlyOwner() {
        require(msg.sender == owner);
        _;
    }
}

contract Derived is Base {
    // Vulnerable: This shadows Base.owner. 
    // The onlyOwner modifier will check Base.owner, not this one.
    address public owner; 
    
    constructor() {
        owner = msg.sender; // Only sets Derived.owner!
    }
    
    function doSomething() public onlyOwner {
        // Will revert if msg.sender != Base.owner (which might be address(0))
    }
}
```

## Safe Example / Remediation
```solidity
contract Derived is Base {
    // Safe: Just use the inherited variable, don't redeclare it.
    constructor() {
        owner = msg.sender; // Properly sets Base.owner
    }
}
```

## False-Positive Conditions & Counterexamples
- **Constructor Arguments**: It is very common for constructor arguments to shadow state variables, e.g., `constructor(address owner) { _owner = owner; }`. Compilers might issue a warning, but it's not a vulnerability if handled correctly. Modern Solidity mitigates this by requiring explicit variable handling or generating warnings.
- **Solidity 0.6+**: The Solidity compiler starting from 0.6.0 throws an error if state variables are shadowed, heavily mitigating this SWC. Therefore, flagging this on a `pragma solidity ^0.8.0;` codebase is usually impossible as it wouldn't compile.

## Solidity-Version Notes
- `< 0.6.0`: Allowed shadowing (silent logic error).
- `>= 0.6.0`: Compiler throws a fatal error on state variable shadowing.
