# SWC-101: Integer Overflow and Underflow

## Summary
An arithmetic operation on a fixed-size integer type produces a result that
falls outside the representable range, causing it to silently wrap around
(e.g. `uint8` 255 + 1 becomes 0, or `uint256` 0 - 1 becomes a huge number).

## Why it matters
If a balance, counter, or allowance wraps around unexpectedly, an attacker
can mint themselves an enormous token balance, bypass a spending limit, or
drain a contract that assumed values could never go negative or exceed a
cap.

## Typical patterns Slither flags
- Manual arithmetic (`+`, `-`, `*`) on `uint`/`int` types without bounds
  checks, particularly in contracts targeting Solidity versions before 0.8.
- Locked-ether patterns where a contract can receive funds but has no
  function decrementing a balance correctly, leaving accounting stuck.

## Typical fix
- Compile with Solidity >= 0.8.0, which reverts on overflow/underflow by
  default.
- For older compiler targets, use OpenZeppelin's `SafeMath` library for all
  arithmetic on user-controlled values.
- Add explicit `require()` bounds checks before subtraction when values
  come from user input.
