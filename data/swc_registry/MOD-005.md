# MOD-005: Flash Loan Attack (General Manipulation)

## Vulnerability Description
While flash loans themselves are a legitimate DeFi tool, they amplify vulnerabilities by granting an attacker near-infinite capital for a single transaction. If a contract's security relies on the assumption that an attacker has limited funds, or if it calculates state based on token balances that can be artificially inflated and deflated within a single block, it is vulnerable to a flash loan attack. This is a broader category that encompasses Oracle Manipulation (MOD-004) and Vault Inflation (MOD-006).

## Severity
High

## Detection Rules & Indicators
- Any logic that uses instantaneous token balances (`token.balanceOf(address(this))`) to calculate share prices, rewards, or voting power.
- Lack of block delays (e.g., requiring users to hold tokens for at least 1 block before voting/claiming rewards).

## Vulnerable Example (Governance / Reward Manipulation)
```solidity
contract VulnerableGovernance {
    ERC20 public governanceToken;
    
    // Vulnerable: Anyone can take a flash loan, deposit, vote, withdraw, 
    // and repay the loan in one block.
    function vote(uint proposalId) public {
        uint votingPower = governanceToken.balanceOf(msg.sender);
        require(votingPower > 1000 ether, "Not enough power");
        // Record vote...
    }
}
```

## Safe Example / Remediation
```solidity
contract SafeGovernance {
    // Safe: Requires snapshots or historical balances, e.g., ERC20Votes
    ERC20Votes public governanceToken;

    function vote(uint proposalId) public {
        // Checks balance at a PAST block, completely neutralizing flash loans
        uint votingPower = governanceToken.getPastVotes(msg.sender, block.number - 1);
        require(votingPower > 1000 ether, "Not enough power");
        // Record vote...
    }
}
```

## False-Positive Conditions & Counterexamples
- **Historical Snapshots**: As shown above, using `getPastVotes` or taking snapshots at prior blocks makes flash loans irrelevant. This is **safe**.
- **Lock-up Periods**: If depositing funds locks them for a minimum of 1 block (or more), a flash loan attacker cannot repay the loan in the same transaction. This is **safe**.

## Solidity-Version Notes
Applies to all versions.

## Related Detectors
- Manual architectural review is essential. Look for instantaneous balance checks determining critical logic.
