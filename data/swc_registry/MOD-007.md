# MOD-007: Signature Replay Attacks

## Vulnerability Description
A smart contract accepts off-chain cryptographic signatures (usually ECDSA) to authorize on-chain actions (like transferring tokens via permit, or claiming an airdrop). If the signature does not include unique identifiers (nonce, chain ID, contract address), an attacker can take a valid signature used in one transaction and "replay" it in another transaction, on another contract, or on another blockchain network (like an L2 or fork).

## Severity
High

## Detection Rules & Indicators
- Usage of `ecrecover` or OpenZeppelin's `ECDSA.recover`.
- A signed payload that lacks `nonce`, `chainid`, or `address(this)`.
- No mechanism to track `executed[signature]` or incrementing nonces per user.

## Vulnerable Example
```solidity
contract VulnerableAirdrop {
    address public signer;
    mapping(address => bool) public claimed; // Missing: doesn't track specific signatures!

    // Vulnerable: Signature doesn't include a nonce. The same signature can be 
    // reused repeatedly if 'claimed' logic is flawed, or replayed on another chain.
    function claim(uint amount, bytes memory signature) public {
        bytes32 messageHash = keccak256(abi.encodePacked(msg.sender, amount));
        bytes32 ethSignedMessageHash = keccak256(abi.encodePacked("\x19Ethereum Signed Message:\n32", messageHash));
        
        require(ecrecover(ethSignedMessageHash, v, r, s) == signer);
        require(!claimed[msg.sender]);
        
        claimed[msg.sender] = true;
        // Send tokens...
    }
}
```

## Safe Example / Remediation
```solidity
// Better yet, use EIP-712!
contract SafeAirdrop {
    address public signer;
    mapping(address => uint) public nonces;

    // Fix: Include chainid, contract address, and user nonce in the hash
    function claim(uint amount, bytes memory signature) public {
        uint currentNonce = nonces[msg.sender];
        bytes32 messageHash = keccak256(
            abi.encodePacked(block.chainid, address(this), msg.sender, amount, currentNonce)
        );
        
        // ... ecrecover logic ...
        
        nonces[msg.sender]++; // Invalidate this signature for future use
        // Send tokens...
    }
}
```

## False-Positive Conditions & Counterexamples
- **EIP-712**: If the contract correctly implements EIP-712 (`DOMAIN_SEPARATOR` includes chain ID and address, and the struct includes a nonce), it is inherently protected from cross-chain and cross-contract replays.
- **Mapping invalidation**: If a signature is just a one-time use coupon, and the contract tracks `usedSignatures[signature] = true`, a nonce might not be strictly necessary for replay protection *on that specific contract*.

## Solidity-Version Notes
Applies to all versions.

## Related Detectors
- Slither: `missing-zero-check` (related to ecrecover returning 0), `tx-origin`. (Signature replays often require manual review).
