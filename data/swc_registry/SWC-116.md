# SWC-116: Block values as a proxy for time

## Vulnerability Description
Contracts often need a source of time (e.g., to enforce deadlines, lockups, or vestings). Using `block.timestamp` (or its alias `now` in older versions) or `block.number` can be slightly manipulated by miners. Miners can adjust the timestamp of a block by a few seconds (usually up to 15 seconds) to favor their own transactions or satisfy a time condition prematurely.

## Severity
Low / Medium

## Detection Rules & Indicators
- Usage of `block.timestamp`, `now`, or `block.number` in logic determining whether a state-changing action can occur or in calculating rewards.

## Vulnerable Example
```solidity
contract Roulette {
    uint public pastBlockTime;

    // Vulnerable: Miner can slightly tweak timestamp to win
    function spin() external payable {
        require(msg.value == 10 ether); 
        require(block.timestamp != pastBlockTime);
        
        pastBlockTime = block.timestamp;
        
        if (block.timestamp % 15 == 0) {
            msg.sender.transfer(address(this).balance);
        }
    }
}
```

## Safe Example / Remediation
```solidity
// For randomness, use a proper oracle (e.g., Chainlink VRF)
// For time-based locks (e.g. weeks/months), block.timestamp is perfectly safe.
contract SafeTimeLock {
    uint public unlockTime;
    
    constructor(uint _unlockTime) {
        unlockTime = _unlockTime;
    }

    function withdraw() public {
        require(block.timestamp >= unlockTime, "Too early");
        // Safe: 15 seconds variance doesn't matter for long-term locks
    }
}
```

## False-Positive Conditions & Counterexamples
- **Long-Term Timelocks**: Using `block.timestamp` for a 1-year vesting schedule, a 24-hour governance delay, or a staking unlock is completely **safe and standard practice**. The 15-second miner manipulation window is immaterial over these time horizons. RAGs should *not* flag every instance of `block.timestamp` as a high-severity vulnerability.
- **Oracles/TWAPs**: Oracles like Uniswap V2/V3 use `block.timestamp` for Time-Weighted Average Prices. While they must be careful, this is the accepted way to track time on-chain.

## Solidity-Version Notes
Applies to all versions. `now` was removed in Solidity 0.7.0.
