# SWC-113: DoS with Failed Call

## Vulnerability Description
A contract iterates over an array of users (e.g., to distribute dividends or refunds) and makes an external call (like transferring ETH) to each one within the loop. If the call fails for *any* user—because they are a malicious contract that reverts in its fallback, or because the call runs out of gas—the entire transaction reverts. This causes a Denial of Service (DoS) for all other users.

## Severity
Medium / High (depending on if funds are permanently locked)

## Detection Rules & Indicators
- A `for` or `while` loop that contains an external call, especially `.transfer()` or `.send()`.
- Iteration over an unbounded array where the array can grow indefinitely, eventually exceeding the block gas limit.

## Vulnerable Example
```solidity
contract VulnerableRefund {
    address payable[] public refundAddresses;
    mapping(address => uint) public refunds;

    function refundAll() public {
        // Vulnerable: If one address is a smart contract that reverts on receive,
        // the entire loop reverts. No one gets their refund.
        for (uint i = 0; i < refundAddresses.length; i++) {
            address payable to = refundAddresses[i];
            require(to.send(refunds[to])); 
        }
    }
}
```

## Safe Example / Remediation
```solidity
contract SafeRefund {
    mapping(address => uint) public refunds;

    // Fix: Pull over Push pattern
    function withdrawRefund() public {
        uint amount = refunds[msg.sender];
        require(amount > 0);
        
        refunds[msg.sender] = 0;
        
        (bool success, ) = msg.sender.call{value: amount}("");
        require(success);
    }
}
```

## False-Positive Conditions & Counterexamples
- **Bounded Loops**: If the array size is strictly limited (e.g., maximum of 5 iterations) and the targets are trusted, gas exhaustion is not an issue.
- **Ignoring Failures (Push pattern done right)**: If the loop continues even when a call fails (e.g., `to.call{value: amount}("");` *without* a `require`), one malicious actor cannot block the others. However, this relies on proper accounting to ensure the failed user doesn't lose funds permanently.
- **Pull over Push**: Contracts that require users to claim their own funds (`withdraw()` style) are inherently protected against this DoS vector.

## Solidity-Version Notes
Applies to all versions.
