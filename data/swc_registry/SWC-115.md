# SWC-115: Authorization through tx.origin

## Summary
A contract uses `tx.origin` (the address that originally started the
transaction chain) instead of `msg.sender` (the immediate caller) to check
who is authorized to perform an action.

## Why it matters
`tx.origin` stays the same across an entire call chain, even through
intermediate contracts. If an authorized user is tricked into calling a
malicious contract, that malicious contract can call the victim protocol on
the user's behalf - `tx.origin` will still show the legitimate user's
address, letting the attacker's contract pass the authorization check and
act as that user (e.g. draining their approved funds).

## Typical patterns Slither flags
- `require(tx.origin == owner)` or any conditional comparing `tx.origin` to
  a stored address, used as an authorization gate.

## Typical fix
- Replace `tx.origin` with `msg.sender` for all authorization checks.
  `tx.origin` should essentially never be used for access control.
