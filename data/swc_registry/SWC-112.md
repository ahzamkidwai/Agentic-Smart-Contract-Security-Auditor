# SWC-112: Delegatecall to Untrusted Callee

## Vulnerability Description
A contract uses `delegatecall` to execute code from an address that is provided by a user or is otherwise untrusted. Because `delegatecall` runs the callee's code in the *caller's* context (preserving storage, `msg.sender`, `msg.value`), an attacker who controls the callee address can execute arbitrary code to overwrite the caller's storage (like the owner or proxy implementation address), drain funds, or destroy the contract.

## Severity
High

## Detection Rules & Indicators
- `delegatecall` where the target address is taken from user input (`msg.data`, function arguments) or from an unauthenticated storage variable.
- Proxies where the implementation logic is user-controlled.

## Vulnerable Example
```solidity
contract Proxy {
    address public owner;

    constructor() {
        owner = msg.sender;
    }

    // Vulnerable: Anyone can pass an arbitrary address to delegatecall to
    function forward(address target, bytes memory data) public {
        (bool success, ) = target.delegatecall(data);
        require(success);
    }
}
```

## Safe Example / Remediation
```solidity
contract SafeProxy {
    address public owner;
    address public implementation;

    constructor(address _implementation) {
        owner = msg.sender;
        implementation = _implementation;
    }

    modifier onlyOwner() {
        require(msg.sender == owner, "Not owner");
        _;
    }

    // Safe: Only owner can change the implementation address
    function upgradeTo(address newImpl) public onlyOwner {
        implementation = newImpl;
    }

    // Safe: target is a trusted state variable
    fallback() external payable {
        address target = implementation;
        (bool success, ) = target.delegatecall(msg.data);
        require(success);
    }
}
```

## False-Positive Conditions & Counterexamples
- **Trusted Callee**: If the `delegatecall` target is a hardcoded address or a known, trusted state variable (like a library or a proxy implementation restricted by access controls), it is **safe**.
- **Libraries**: `delegatecall` is used under the hood when calling external libraries. This is completely safe if the library address is fixed at compile/deploy time.
- **Multicall**: The `Multicall` pattern often uses `delegatecall` to batch calls *to itself*. Since it's delegating to `address(this)`, it is **safe** (assuming the target functions are secure).

## Solidity-Version Notes
Applies to all versions.
