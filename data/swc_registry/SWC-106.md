# SWC-106: Unprotected SELFDESTRUCT

## Vulnerability Description
A contract includes a `selfdestruct` (or `suicide` in older versions) operation that is accessible to unauthorized users. An attacker can call this function to destroy the contract, wiping its code and storage, and forwarding any remaining Ether balance to an attacker-controlled address.

## Severity
High

## Detection Rules & Indicators
- `selfdestruct(recipient)` in a `public` or `external` function without adequate access control (e.g., `onlyOwner` or multi-sig consensus).

## Vulnerable Example
```solidity
contract VulnerableMortal {
    // Missing access control, anyone can kill the contract
    function kill() public {
        selfdestruct(msg.sender);
    }
}
```

## Safe Example / Remediation
```solidity
contract SafeMortal {
    address payable public owner;

    constructor() {
        owner = payable(msg.sender);
    }

    // Only owner can destroy the contract
    function kill() public {
        require(msg.sender == owner, "Unauthorized");
        selfdestruct(owner);
    }
}
```

## False-Positive Conditions & Counterexamples
- **Proper Access Control**: If `selfdestruct` is protected by a modifier (like `onlyOwner`) or is inside an internal function only reachable by the admin, it is safe.
- **Disposable Contracts (e.g., CREATE2 Metamorphic)**: Sometimes contracts are intentionally designed to be destroyed and recreated (metamorphic contracts) to bypass bytecode immutability. If anyone is *intended* to destroy them (e.g., after a specific state is reached), it may not be a vulnerability, but rather a design choice.

## Solidity-Version Notes
- **EIP-6780 (Dencun Upgrade)**: As of the Ethereum Dencun upgrade, `selfdestruct` no longer destroys the contract code/storage unless it was created in the *same transaction*. It only sends the ETH balance to the target address. Thus, in modern contexts, it acts more like a forced ETH transfer than a contract-killing operation. However, unauthorized use is still a vulnerability (stealing funds).
