# MOD-010: Missing Access Control (General)

## Vulnerability Description
While SWC-105 specifically covers unprotected *Ether* withdrawals, modern smart contracts have many critical functions that don't directly move ETH but still require strict authorization. This includes pausing the contract, minting tokens, updating fee percentages, changing oracle addresses, or modifying user roles. If these functions lack access control, any user can execute them, severely disrupting or compromising the protocol.

## Severity
High

## Detection Rules & Indicators
- State-mutating functions that change critical parameters (e.g., `setFee`, `updateOracle`, `pause`, `mint`) without modifiers like `onlyOwner` or `onlyRole`.
- A `public` or `external` function that should be `internal` or `private`.

## Vulnerable Example
```solidity
contract VulnerableAMM {
    uint public swapFee = 300; // 0.3%

    // Vulnerable: Missing onlyOwner. Anyone can set the fee to 100% (100000)!
    function setFee(uint newFee) public {
        require(newFee <= 100000);
        swapFee = newFee;
    }
}
```

## Safe Example / Remediation
```solidity
contract SafeAMM {
    uint public swapFee = 300;
    address public admin;

    modifier onlyAdmin() {
        require(msg.sender == admin, "Not Admin");
        _;
    }

    // Safe: Protected by modifier
    function setFee(uint newFee) public onlyAdmin {
        require(newFee <= 10000); // Also added a sane upper bound constraint
        swapFee = newFee;
    }
}
```

## False-Positive Conditions & Counterexamples
- **Public Getters**: Functions that do not modify state (`view` or `pure`) generally do not need access control and are perfectly safe as `public`.
- **Intended Permissionless Functions**: Functions like `poke()`, `updateState()`, or `harvest()` in DeFi are often intentionally permissionless so anyone (or bots) can call them to trigger necessary system maintenance. RAG should not flag a state-changing function as vulnerable *just* because it lacks `onlyOwner`, unless it changes critical admin-level parameters.
- **Internal Access Control**: The function might not have a modifier, but the very first line is `require(msg.sender == admin)`. This is functionally identical to a modifier and is **safe**.

## Solidity-Version Notes
Applies to all versions.
