# MOD-002: Cross-Contract Reentrancy

## Vulnerability Description
Similar to cross-function reentrancy, but the shared state exists across *multiple* smart contracts that belong to the same protocol (e.g., a Vault contract and a Strategy contract, or an AMM Router and Pair). One contract makes an external call to an attacker while its state (or the state of a sister contract it relies on) is inconsistent. The attacker then calls into a *different* contract in the protocol that reads the inconsistent state.

## Severity
High

## Detection Rules & Indicators
- Complex protocols with multiple interacting contracts sharing state or relying on each other's balances/reserves.
- A standard reentrancy guard (`nonReentrant`) on one contract, but it does *not* lock the sister contracts.

## Vulnerable Example
```solidity
contract ProtocolToken {
    Vault public vault;
    uint public totalSupply;
    
    // ...
}

contract Vault {
    ProtocolToken public token;
    
    function withdraw(uint amount) public {
        token.burn(msg.sender, amount); // Burns tokens
        
        // External call. Vault state is fine, but ProtocolToken supply is lowered.
        // What if another contract relies on Vault balance vs Token supply?
        (bool success, ) = msg.sender.call{value: amount}(""); 
        require(success);
    }
}
```

## Safe Example / Remediation
```solidity
// Fix: Use a protocol-wide reentrancy lock.
contract ProtocolLock {
    uint private _status;
    modifier nonReentrant() { ... }
}

contract Vault is ProtocolLock {
    function withdraw(uint amount) public nonReentrant {
        // ...
    }
}

contract SisterContract is ProtocolLock {
    // Shares the same storage slot/lock logic as Vault via a shared proxy or 
    // explicit cross-contract mutex call.
    function doSomething() public nonReentrant {
        // ...
    }
}
```

## False-Positive Conditions & Counterexamples
- **No Shared State Dependency**: If Contract A and Contract B do not read each other's state during their respective functions, they do not need a shared lock.
- **Cross-Contract Locks**: Some protocols implement a central `ReentrancyRegistry` or require `require(!vault.isLocked())`. This is **safe** and effectively mitigates the issue.

## Solidity-Version Notes
Applies to all versions.

## Related Detectors
- Very difficult for static analyzers like Slither to detect. Requires invariant testing (Echidna/Foundry) or manual architecture review.

## References
- Common in modern DeFi hacks (e.g., MakerDAO, Curve logic interacting with external view functions).
