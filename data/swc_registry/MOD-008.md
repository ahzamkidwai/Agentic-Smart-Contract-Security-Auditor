# MOD-008: Storage Collisions (Proxy Patterns)

## Vulnerability Description
When using proxy patterns (like Transparent or UUPS), the proxy contract delegates calls to an implementation contract but executes them in the context of the *proxy's* storage. If the proxy declares state variables in the same order/slots as the implementation, or if a new implementation changes the order/types of variables from the previous version, the storage slots will overlap. A variable written by the implementation might accidentally overwrite critical proxy data, or vice-versa.

## Severity
High

## Detection Rules & Indicators
- Proxy contracts declaring state variables (other than via structured storage like EIP-1967).
- Upgraded implementations changing the inheritance order, inserting new variables before existing ones, or changing variable types (e.g., `uint8` to `uint256`).

## Vulnerable Example
```solidity
contract VulnerableProxy {
    // Slot 0: owner
    address public owner; 
    address public implementation;

    fallback() external {
        implementation.delegatecall(msg.data);
    }
}

contract ImplementationV1 {
    // Slot 0: also owner!
    // Slot 1: balance
    address public implementationOwner;
    uint public balance;
    
    function initialize() public {
        // Vulnerable: This overwrites the Proxy's 'owner' variable in Slot 0!
        implementationOwner = msg.sender;
    }
}
```

## Safe Example / Remediation
```solidity
// Proxy: Use EIP-1967 unstructured storage slots to avoid slot 0 collisions
contract SafeProxy {
    // bytes32(uint256(keccak256('eip1967.proxy.implementation')) - 1)
    bytes32 constant IMPLEMENTATION_SLOT = 0x360894a13ba1a3210667c828492db98dca3e2076cc3735a920a3ca505d382bbc;
    
    // ... use assembly to read/write this slot
}

// Implementation: Append only!
contract ImplementationV1 {
    uint public var1;
}

contract ImplementationV2 is ImplementationV1 {
    // Safe: New variables are always appended to the END.
    uint public var2; 
}
```

## False-Positive Conditions & Counterexamples
- **Diamond Pattern / AppStorage**: Uses entirely different storage layouts (often a struct placed at a specific hash) to avoid standard sequential slot collisions.
- **EIP-1967**: Modern proxies (OpenZeppelin) use unstructured storage for proxy-specific variables, making them **safe** from colliding with implementation variables.

## Solidity-Version Notes
Applies to all versions.
