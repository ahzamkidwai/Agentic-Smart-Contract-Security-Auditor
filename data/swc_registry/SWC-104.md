# SWC-104: Unchecked Call Return Value

## Vulnerability Description
Solidity's low-level calls (`call`, `delegatecall`, `staticcall`, `send`) return a boolean indicating success instead of reverting automatically on failure. If the caller does not check that boolean, a failed call is silently ignored, and the contract continues execution assuming the call succeeded. This often happens with older non-standard ERC-20 tokens that return `false` on failure instead of reverting.

## Severity
Medium / High (Context dependent)

## Detection Rules & Indicators
- `.call{value: x}("")`, `.send()`, or `token.transfer(...)` whose return value is neither checked in a `require` nor assigned to a variable that is later checked.

## Vulnerable Example
```solidity
contract Payout {
    function withdraw(uint amount) public {
        require(balances[msg.sender] >= amount);
        balances[msg.sender] -= amount;
        
        // Return value is not checked. If this fails, the user loses their balance internally
        // but receives no ETH.
        msg.sender.call{value: amount}(""); 
    }
}
```

## Safe Example / Remediation
```solidity
contract Payout {
    function withdraw(uint amount) public {
        require(balances[msg.sender] >= amount);
        balances[msg.sender] -= amount;
        
        (bool success, ) = msg.sender.call{value: amount}("");
        require(success, "Transfer failed");
    }
}
```

## False-Positive Conditions & Counterexamples
- **Return value checked**: If the call is wrapped in a `require`, or the returned bool is checked, it is **safe**. Example: `require(ERC20(token).transfer(to, amount));`
- **SafeERC20**: If using OpenZeppelin's `SafeERC20` wrapper (`token.safeTransfer(to, amount)`), it reverts on failure. This is **safe**.
- **Deliberate Ignoring**: Sometimes a contract intentionally ignores the return value because the failure of the external call shouldn't block execution (e.g., a "best effort" airdrop or logging). This requires manual review, but the RAG should recognize that if a comment says `// Ignore revert`, the developer did it intentionally.

## Solidity-Version Notes
No compiler version fixes this automatically; developers must handle return values manually.
